# Santomi — спецификация движения и микровзаимодействий

## Принцип
Анимация должна объяснять переход, подтверждать действие или усиливать **один особенный момент** — раскрытие получателя. Это не постоянная новогодняя заставка. Центральные 3D-иллюстрации допускают деликатную живость, но длинные частицы, снег и вспышки не должны закрывать содержимое.

## Общие motion tokens (ориентиры, уточнять на устройствах)
| Действие | Длительность | Движение |
|---|---:|---|
| Нажатие CTA | 90–150 мс | scale 1 → 0.97 → 1, без задержки самого действия |
| Переход экранов | 220–320 мс | opacity + translateY/translateX 6–16px, направление соответствует навигации |
| Bottom sheet | 280–360 мс | снизу вверх, spring без заметного bounce, backdrop opacity |
| Карточка входит | 240–340 мс | opacity + translateY 12px |
| Stagger карточек | 35–60 мс между карточками | максимум 4–6 видимых элементов |
| Переключатель/чип | 120–220 мс | цвет + scale и чек-марка |
| Добавить/убрать желание | 180–280 мс | layout transition; соседние карточки перестраиваются |
| Новое сообщение | 140–220 мс | лёгкий slide вверх + opacity без анимации всей истории |
| Feedback / toast | 180–240 мс | появление, затем автоисчезновение при достаточном времени чтения |
| Загрузка AI | пока длится настоящий запрос | мягкая циклическая индикация с периодом ~1,5–2,5 c |
| Раскрытие получателя | 1,4–2,2 c максимум | отдельный сценарий ниже; всегда есть Skip |

Easing: для UI `cubic-bezier(0.22,1,0.36,1)`; для sheet мягкий spring без «резинки»; уважать `prefers-reduced-motion`. Не фиксировать `100vh`: использовать безопасные единицы и `safe-area-inset-*`.

## Сценарии по экранам
- **01 Онбординг:** заголовок появляется в 2–3 фазах, затем подарочная иллюстрация с scale 0.96→1, затем CTA; подарок едва качается ±1–2° с периодом 6–9 с, только пока экран активен. Не делать обязательный swipe вместо обычного нажатия.
- **02 Главная:** первая большая карточка мягко выезжает, быстрые действия без «прыжков», список комнат stagger максимум 4 элемента; обновление статуса не анимирует весь экран.
- **03 Создание:** переход между шагами с translate 10px и fade; фокус поля не сдвигает кнопку под клавиатуру; ошибки ввода подсвечиваются коротким переходом, без shake.
- **04 Приглашение:** конверт один раз поднимается 10px, при копировании toast и лёгкий haptic; QR не анимировать постоянно.
- **05 Комната:** progress по числу готовых вишлистов обновляется плавно за ~400 ms; карточки участника/даты статичные при отсутствии данных.
- **06 Участники:** табы crossfade 150–200 ms, новые строки fade+slide, исключения чипами с выходом и перераскладкой.
- **07 Интересы:** выбранная категория слегка уменьшается при касании, затем возвращается с check-плашкой и мягким контуром; картинки не улетают и не перескакивают.
- **08 Вишлист:** добавление/удаление вызывает layout reflow, сохранение показывает status toast; горизонтальный selector плавно скроллится вручную, не авто-прокручивать бесконечно.
- **09 Жеребьёвка:** перед вызовом сервера организатор видит подтверждение; пока сервер занят, ограниченная анимация свечения сферы/иконки; успех не должен раскрывать список пар.
- **10 Раскрытие — герой:** `idle` → `tap` (120ms уменьшение) → `opening` (500–750ms движение крышки/конверта) → `glow` (200–300ms, умеренно) → `recipient-card` (300–450ms поднимается) → `done`. Вся анимация 1,4–2,2 секунды. `Skip` выводит конечное состояние мгновенно; состояние не влияет на серверное назначение. Для reduced motion показывать карточку простым fade. Не обязательно использовать WebGL; лучше лёгкие Lottie/Rive/отрисованные последовательности только при наличии подходящих проверенных ассетов, иначе Motion/CSS.
- **11 Чат:** входящее сообщение появляется единожды; автоскролл только если просмотрен низ чата; клавиатура и системная панель Telegram не перекрывают поле; `typing` только при реальном наличии события.
- **12 Gift AI:** пока запрос в работе — спокойно «дышит» робот или бегут 3 точки; реальные рекомендации появляются по одной, максимум 5 карточек в stagger; не вставлять намеренные паузы и не симулировать стриминг.
- **13 Paywall:** один световой блик на герое при входе; обработчик оплаты не зависит от анимации; возврат по закрытию invoice обрабатывается.
- **14 Профиль:** аватар и секции появляются без flashy переходов, переключатели состояния понятны без движения.

## Производительность и безопасность
- Анимировать в основном `transform` / `opacity`; избегать больших blur и непрерывных фильтров на всём viewport.
- Не создавать десятки канвас-частиц поверх формы/чата; отключать амбиентные эффекты при уходе со страницы и при `prefers-reduced-motion`.
- Избегать дополнительных тяжёлых библиотек ради одной кнопки; по умолчанию Motion for React + CSS. Originkit использовать выборочно **только после проверки доступности кода, лицензии, размера bundle и адаптации**.
- Анимация не подменяет фактический результат сервера, работу оплаты, права доступа и приватность жеребьёвки.
- Использовать Playwright для проверки кликабельности после анимации, тестировать узкие viewport и скролл, проводить визуальное сравнение скриншотов (не claim «60fps» без измерений).
