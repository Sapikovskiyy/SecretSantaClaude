# Santomi — техническое задание на UX/UI 14 экранов

**Статус:** дизайн-хэндoff для реализации в существующем React + TypeScript Telegram Mini App.  
**Владелец продукта:** заказчик/CEO.  
**Цель:** воспроизвести **визуальную логику** макетов 01–14 в одном работающем приложении, не склеивать интерфейс из картинок и не заменять существующие функции демоданными.  
**Материалы:** `references/00_original_style_reference.png` — исходный художественный ориентир; листы `01...04` — согласованная предметная структура 14 экранов.

## 1. Приоритеты источников
1. **Четыре листа 14 экранов:** структура, назначение компонентов, композиция, контентные зоны, сценарии.
2. **Оригинальный трёхэкранный референс:** ощущение дизайна — смелая типографика, большие 3D-объекты, простор, красный/зелёный/шоколадный, простые интеракции. Его стиль должен удержать макеты от превращения в перегруженный новогодний каталог.
3. **Живое UX, безопасность и адаптивность** имеют приоритет над буквальным повторением ошибочных надписей, дат или нарисованных элементов макетов.

Изображения являются **референсом, а не готовым экраном**. Нельзя вставлять в приложение JPG/PNG целого телефона, имитировать работу кнопок поверх картинки или выдавать UI-коллажи за исходные иллюстрации. Требуются настоящие React-компоненты, DOM, управляемое состояние, реальные переходы.

## 2. Визуальная система
- **Позиционирование:** тёплый праздничный премиум, дизайнерское мобильное приложение, не SaaS и не детская игрушка.
- **Фоны:** шоколадный `#281D19` / тёмный `#1D1512`; глубокий зелёный `#006B43`; фирменный красный `#D5361C`; поверхности кремовый `#FFE4CE` и `#FFF9F2`. Золотые световые акценты `#E6B96C`, умеренно.
- **Типографика:** 2 роли: выразительный крупный serif-display с полной поддержкой кириллицы (например, Prata) для эмоциональных заголовков и лаконичный sans (например, Manrope) для интерфейса. Учитывать доступность шрифтов; избегать зависимости от недоступной внешней CDN при запуске из РФ.
- **Сетка:** mobile-first, 320–430 CSS px и широкие телефоны; внутренняя горизонтальная отбивка 20–24 px, минимальная зона касания ~44×44 px; логические радиусы для чипов 16–22, для панелей 24–32.
- **Карточки:** кремовые поверхности на шоколадном фоне, асимметричные полноэкранные композиции, крупные округлые CTA. Карточек ровно столько, сколько нужно для принятия решения.
- **3D:** 3D-иллюстрации подарков, саней, Деда Мороза, домика, книг, чашек, наушников, конвертов. Один язык материалов (мягкий пластик/глина/тактильные предметы), света и ракурсов. Для важных сцен нужны отдельные разрешённые ресурсы; коллажи макетов не являются пригодными исходными ассетами. Эмодзи допускаются в микротексте, не как центральная графика.
- **Иконки:** единое семейство, максимум 2 веса, без случайного смешения стилей. Русский интерфейс на всех экранах.
- **Навигация:** логичные экранные сценарии, кнопка «Назад»; нижняя навигация только где действительно полезна. Внутри Telegram соблюдать safe areas и Telegram Back Button.
- **Компоненты:** `ScreenShell`, `PageHeader`, `PrimaryCTA`, `CreamSheet`, `GiftIllustration`, `RoomCard`, `ParticipantRow`, `InterestTile`, `WishItem`, `StatusPill`, `BottomSheet`, `Toast`, `FormField`, `EmptyState`, `LoadingState`, `ErrorState`, `GiftReveal`.

## 3. Точная карта экранов

### 01 · Онбординг / Welcome
**Макет:** лист 01, экран 01. Полный шоколадный экран, гигантский заголовок «Время Тайного Санты!», один доминирующий 3D-подарок, красная CTA «Начать» и второстепенная «Присоединиться к игре».  
**Поведение:** «Начать» открывает главный экран/вход через Telegram; приглашение с `startapp` сохраняется и открывает нужную комнату. Не показывать онбординг при каждом открытии.  
**Состояния:** первый запуск; возвращающийся пользователь; пришёл по ссылке.  
**Анимация:** поэтапное появление заголовка/подарка/CTA, очень медленное «дыхание» объекта; запуск ≤0,9 с.

### 02 · Главная / Home
**Макет:** лист 01, экран 02. Шоколадный фон, компактный профиль, большой зелёный праздничный герой-блок, три быстрых действия и карточки активных игр.  
**Поведение:** создать игру, открыть комнаты, перейти к Gift AI, открыть комнату из списка; динамический статус комнаты.  
**Состояния:** нет игр; активные; завершённые; подгрузка; ошибка.  
**Анимация:** hero мягко появляется; карточки смещаются на 8–12 px с коротким stagger.

### 03 · Создание игры / Create Room
**Макет:** лист 01, экран 03. Верхняя сцена с красными санями и подарками, кремовый нижний лист, форма и красная CTA.  
**Поля:** имя, бюджет, дата, ограничение участников, анонимный чат; в дальнейшем исключения.  
**Поведение:** валидация, реальное создание через API в production; переход к приглашению. При ошибке данные формы сохраняются.  
**Анимация:** плавная смена шагов и подсветка ошибок; без полного рестарта формы.

### 04 · Приглашение друзей / Invite
**Макет:** лист 01, экран 04. Красный конверт, кремовая сводка, аватары, ссылка, крупная синяя кнопка Telegram.  
**Поведение:** ссылка на конкретную комнату, копирование, Telegram Share, просмотр/обновление состава; QR-код только если он сгенерирован из действительного URL.  
**Состояния:** приглашение скопировано; лимит достигнут; недоступная ссылка; загрузка.  
**Анимация:** конверт выезжает/чуть раскрывается при открытии, toast при копировании.

### 05 · Комната / Room Dashboard
**Макет:** лист 02, экран 05. Иллюстрация заснеженного домика, кремовая панель с названием, бюджетом, датой, прогрессом и действиями.  
**Поведение:** перейти к участникам, приглашению, настройкам, вишлистам; кнопка жеребьёвки видна лишь организатору и только когда допустимо.  
**Состояния:** сбор участников / ожидание / жеребьёвка завершена / обмен / завершено.  
**Анимация:** progress плавно меняется; кнопки мягко реагируют на касания.

### 06 · Участники и исключения / Participants
**Макет:** лист 02, экран 06. Список участников на кремовой поверхности, табы «Участники / Исключения / Пары» (таб «Пары» НЕ должен раскрывать секретные назначения).  
**Поведение:** приглашение, исключения вида A не дарит B, статус заполнения вишлистов, напоминания; раздел настроек пар — только для правил, не просмотра назначений.  
**Состояния:** пусто / добавляются / часть готова / всё готово; ошибки ограничений.  
**Анимация:** add/remove рядов, переключение табов, мягкие чипы исключений.

### 07 · Интересы / Interests
**Макет:** лист 02, экран 07. Зелёный/шоколадный фон, большой заголовок «Какие у вас интересы?», визуальная сетка 2 столбца: книги, кофе, игры, технологии, музыка, дом и др.  
**Поведение:** множественный выбор; сохранение интересов; CTA «Продолжить»; действия работают на touch.  
**Состояния:** ничего не выбрано / выбрано / сохранение / ошибка.  
**Анимация:** селект масштаба 0.97→1.0, чек-марка, мягкая перестановка/выделение; без тяжёлых 3D WebGL сцен.

### 08 · Вишлист / Wishlist
**Макет:** лист 02, экран 08. Тёмный верх, горизонтальная полоса миниатюр товаров, кремовая большая форма редактирования.  
**Поведение:** добавить, редактировать, удалить желание; цена, приоритет, ссылка, примечания; запрещённые подарки отдельно; пользователь видит реальные сохранённые данные.  
**Состояния:** пустой список / список / редактирование / сохранено / ошибка URL.  
**Анимация:** layout transitions списка, mini item scale и реакция на сохранение; сохранение не блокировать декоративной анимацией.

### 09 · Жеребьёвка / Draw Preparation
**Макет:** лист 03, экран 09. Объёмный Санта со сферой, кремовый список участников, крупная красная CTA.  
**Поведение:** показать число участников, невозможные исключения, подтвердить запуск. Жеребьёвку выполняет **только сервер** одной атомарной операцией, один раз; повторные вызовы идемпотентны.  
**Состояния:** ещё нельзя / готово / выполняется / ошибка / завершено.  
**Анимация:** подвижные звёзды только фоном; на подтверждении короткая анимация подготовки, реальный ответ сервера не подменять.

### 10 · Кому ты даришь / Recipient Reveal
**Макет:** лист 03, экран 10. Большая раскрытая подарочная коробка, персональная карточка и CTA «Посмотреть вишлист».  
**Поведение:** открыть сохранённый серверный результат, перейти к вишлисту и анонимному общению; для получателя не раскрывать личность дарителя.  
**Состояния:** не проведено / загружается / назначено / ошибка доступа.  
**Анимация:** сценарная фирменная 1,4–2,2 с, возможность пропуска; не генерировать новую пару на клиенте.

### 11 · Анонимный чат / Anonymous Chat
**Макет:** лист 03, экран 11. Шоколадный фон, 2 цвета пузырей, header «Твой Тайный Санта», подсказки и компактная composer-панель.  
**Поведение:** **двусторонний** чат; Санта видит адресата, получатель — только псевдоним «Твой Тайный Санта»; серверная проверка авторизации; временные метки, отправка, ошибочный retry, жалоба.  
**Состояния:** пустой чат / отправляется / доставлено / ошибка / недоступно; клавиатура не перекрывает ввод.  
**Анимация:** новые сообщения fade+rise 120–220 ms, без переанимации истории; автоскролл лишь если пользователь у последнего сообщения.

### 12 · Gift AI / AI Gift Assistant
**Макет:** лист 03, экран 12. Тёмная верхняя сцена с роботом Санта, кремовая зона фильтров и рекомендаций.  
**Поведение:** выбрать бюджет, интересы, сведения о получателе, подбирать подарки с Yandex AI **через сервер**; сохранять идеи; уточняющие вопросы; AI ограничен темой подарков.  
**Состояния:** до запроса / запрос / 5 рекомендаций / ошибка / исчерпан лимит / API не настроен.  
**Анимация:** мягкая пульсация робота во время запроса, stagger карточек, не генерировать фиктивные реальные ссылки или цены.

### 13 · AI Plus / Paywall
**Макет:** лист 04, экран 13. Большой premium-display заголовок, робот с подарком, кремовые преимущества, большая CTA; декор минимален.  
**Поведение:** показать лимиты, цену **в Telegram Stars**, срок доступа, условия продления; открыть реальный Telegram Stars invoice в production.  
**Состояния:** не оформлено / оплачивается / оплачено / ошибка / подписка закончилась.  
**Анимация:** однократный лёгкий световой акцент, корректная обработка возвращения из оплаты; не активировать премиум до проверки платежа сервером.

### 14 · Профиль / Profile
**Макет:** лист 04, экран 14. Шоколадный верх с аватаром, кремовые секции «Активные игры», «Прошлые игры», «Вишлисты», уведомления/помощь.  
**Поведение:** профиль Telegram, комнаты, прошлые игры, настройки, статус AI Plus; **не добавлять «выйти из Telegram»**, если отдельный вход не реализован.  
**Состояния:** новый пользователь / есть история / загрузка / ошибка.  
**Анимация:** деликатные входы секций, статус подписки без постоянного свечения.

## 4. Пользовательские сценарии, которые должны работать
A. Первый запуск → создание комнаты → приглашение → ожидание участников → жеребьёвка → раскрытие → вишлист получателя → анонимный чат.  
B. Приглашённый через Telegram → подтверждение присоединения → свои интересы и вишлист → ожидание → свой результат.  
C. Редактирование вишлиста → актуализация комнаты → новый статус без перезагрузки всего приложения.  
D. AI → получение рекомендаций → сохранение идеи → упёрся в лимит → AI Plus/оплата (только действительные интеграции в production).  
E. Повторное открытие комнаты и приложения должно сохранять состояние и не возвращать пользователя к онбордингу.

## 5. Дизайн ошибки в мокапах, которые НЕ нужно копировать
- В картинках встречаются **2024/2025**: заменить реальными или текущими демодатами, не кодировать дату в изображениях.
- Цены товаров и реальные магазинные предложения на иллюстрациях — декоративные примеры; без каталога/реального API нельзя выдавать их за актуальные.
- «100 ₽» на экране премиума — маркетинговая гипотеза, не точная цена Stars; показывать корректную цену, подтверждённую оплатой.
- «Пары» для организатора не должны раскрывать участников жеребьёвки.
- Отображаемый никнейм, лица, имена, фотографии в макетах — демонстрационные данные, не хардкодить.
- Не добавлять ложные QR-коды, кнопки оплаты, активные соединения или сообщения AI.

## 6. Технические и UX-требования
- Existing React + TypeScript + Vite, использовать существующую архитектуру; Supabase Edge Functions и PostgreSQL для сервера; Telegram Mini Apps SDK; Cloudflare Workers Static Assets для фронтенда.
- Роуты должны работать при обновлении (`SPA fallback`); поддержка Android, iOS, Telegram WebView, PWA shell, safe-area, viewport changes, reduced motion.
- Никогда не держать Telegram bot token, Yandex API key, Supabase service-role key в клиентском bundle.
- JWT/Telegram `initData` проверяются на сервере. Пользователь не видит чужих пар или сообщений по ошибке API/RLS.
- Демо и production разделены видимым флагом; demo допускает локальные данные, production — только реальные бэкенд-операции.
- Loading/error/empty/success состояния всех сетевых операций обязаны быть спроектированы.
- Не использовать параллельно много анимационных библиотек: по умолчанию Motion for React + CSS, выборочно готовые Originkit-компоненты при наличии и проверке лицензии.
- Доступность: читаемый текст, контраст, управление с клавиатуры там, где возможно, не полагаться на цвет как единственный статус, `prefers-reduced-motion`.

## 7. Передача дизайна в разработку и процесс согласования
1. **Аудит:** открыть текущий код, проверить 14 экранов и внешние зависимости, не переписывать проект с нуля без согласования.
2. **Дизайн-фундамент:** токены + шрифты + компоненты; показать **01, 07, 08, 11** как визуальный срез; получить одобрение CEO.
3. **Весь UI:** собрать 14 экранов с фейковыми данными строго в Demo Mode, провести скриншот-сравнение с листами; отдельный чеклист отсутствующих состояний.
4. **Подключение существующих функций:** реальные обработчики маршрутов/форм/API; не сломать комнаты, жеребьёвку, чат и AI.
5. **Тесты:** unit для функций, Playwright для основных маршрутов на 390×844 и 360×800 (по возможности устройства), скриншоты, `npm run build`.
6. **Приёмка:** CEO проверяет preview; только после согласования разрешить push / Cloudflare deploy.

## 8. Критерии готовности
- Все 14 экранов присутствуют и визуально согласованы; кнопки реально работают; нет горизонтального скролла на 320–430 px.
- Большие 3D-объекты оформлены единообразно; текст нигде не перекрывается. UI — DOM, а не картинка экрана.
- На 01/07/08/11 видно узнаваемое родство с исходным трёхэкранным референсом.
- Создание комнаты, join, вишлист, draw, reveal, чат проверены в соответствующем режиме; секретные данные не раскрываются.
- Нет неожиданных/вечных анимаций, нет ломания клавиатуры и WebView.
- Сборка компилируется; Playwright-проверки оформлены с фактическими результатами; пробная публикация только с согласия CEO.
